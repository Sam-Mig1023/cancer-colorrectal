PLAN DE TRABAJO DEL DATASET, STREAMLIT, FASTAPI Y NEXT.JS
Proyecto: Sistema de diagnostico de cancer colorrectal
Fecha: 19 de julio de 2026

======================================================================
1. OBJETIVO
======================================================================

El objetivo es cumplir las indicaciones del docente manteniendo una
arquitectura compuesta por:

- Next.js, React y Tailwind CSS como frontend principal.
- FastAPI como backend central y unica fuente de verdad.
- Streamlit como consola cientifica y administrativa.
- Python y TensorFlow para los procesos de redes neuronales.
- Modelos .h5 para inferencia desde FastAPI.
- Dataset real para EDA, entrenamiento, validacion cruzada, evaluacion,
  seleccion del mejor modelo, pruebas estadisticas y reportes.

No se reemplazara Next.js por Streamlit. Tampoco se colocara toda la logica
cientifica dentro de Streamlit. Streamlit y Next.js consumiran los servicios
de FastAPI.

Responsabilidades:

2.1. Next.js

- Interfaz para el usuario final.
- Español e ingles.
- Modo claro y oscuro.
- Chatbot escrito y por voz.
- Carga de imagenes.

- Explicabilidad cuando corresponda.

- Informacion resumida del dataset y del modelo activo.

Next.js no debe abrir directamente los archivos .h5 ni acceder directamente
a las 100,000 imagenes. Envia solicitudes a FastAPI.

2.2. FastAPI

- Carga los modelos .h5.
- Ejecuta las predicciones.
- Administra el dataset.
- Administra trabajos largos.
- Ejecuta EDA, entrenamiento y evaluacion.
- Implementa validacion cruzada.
- Ejecuta busqueda de hiperparametros.
- Calcula pruebas estadisticas.
- Selecciona y registra el mejor modelo.
- Genera reportes y artefactos reproducibles.
- Expone endpoints para Next.js y Streamlit.

2.3. Streamlit

- Funciona como consola cientifica del profesor y del equipo.
- Permite preparar el dataset.
- Muestra estado y progreso.
- Ejecuta EDA.

- Configura validacion cruzada e hiperparametros.
- Ejecuta evaluaciones.
- Compara modelos.
- Muestra pruebas estadisticas.
- Permite descargar reportes tecnicos.

Streamlit no debe duplicar los calculos de FastAPI. Debe consumir la API.

3. DATASETS QUE UTILIZAREMOS
======================================================================

3.1. NCT-CRC-HE-100K

Uso:

- Entrenamiento.
- Validacion interna.
- Validacion cruzada.
- Busqueda de hiperparametros.
- EDA.

Caracteristicas:

- 100,000 imagenes histologicas.
- Resolucion 224 x 224 pixeles.
- Nueve clases: ADI, BACK, DEB, LYM, MUC, MUS, NORM, STR y TUM.
- Imagenes H&E normalizadas por color.

3.2. CRC-VAL-HE-7K

Uso:

- Test externo final.
- Comparacion final de modelos.
- Pruebas estadisticas pareadas.

Caracteristicas:

- 7,180 imagenes.
- Mismas nueve clases.
- Resolucion 224 x 224 pixeles.
- Pacientes sin solapamiento con NCT-CRC-HE-100K segun la publicacion.

Fuente academica oficial:

https://zenodo.org/records/1214456

DOI:

https://doi.org/10.5281/zenodo.1214456

Proveedor tecnico posible:

https://huggingface.co/datasets/1aurent/NCT-CRC-HE

Zenodo sera la referencia academica oficial. Hugging Face puede utilizarse
para visualizacion, streaming o sincronizacion tecnica. Se debe documentar
que la publicacion de Hugging Face es una copia comunitaria.

======================================================================
5. FLUJO GENERAL DEL DATASET
======================================================================

1. El usuario autorizado abre Streamlit.
2. Entra en Gestion del dataset.
3. Selecciona la fuente.
4. Presiona Preparar dataset.
5. Streamlit solicita a FastAPI iniciar un trabajo.
6. FastAPI descarga o sincroniza los datos.
7. FastAPI verifica archivos y clases.
8. FastAPI genera el manifiesto.
9. FastAPI genera particiones y folds reproducibles.
10. FastAPI calcula checksums y fingerprint.
11. FastAPI marca el dataset como preparado.
12. Streamlit habilita EDA, entrenamiento y evaluacion.

La transferencia del dataset es inevitable para entrenar o evaluar todas las
imagenes. Sin embargo, la descarga sera automatica, reanudable y persistente.
El usuario no tendra que descargar y organizar manualmente los 15 GB.

PASO 13. SELECCIONAR EL MEJOR MODELO
---------------------------------------------------------------------

Regla recomendada:

1. Mayor Macro F1 promedio en validacion cruzada.
2. En caso de empate, mayor MCC promedio.
3. Menor desviacion entre folds.
4. Como criterios operativos, menor tamaño y tiempo de inferencia.

Acciones:

- Comparar solamente experimentos compatibles.
- Verificar mismo dataset, fingerprint y folds.
- Registrar la decision.
- Reentrenar el ganador con la configuracion seleccionada.
- Evaluarlo una sola vez en CRC-VAL-HE-7K.
- Exportar el modelo a .h5.

Resultado esperado:

- Modelo ganador con evidencia reproducible.

Criterio de finalizacion:

- La seleccion no depende de valores escritos manualmente.
